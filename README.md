# ByPass Cleaner

Desktop utility for controlled file cleanup on Windows with preview mode, live metrics, reports, process inspection, and quarantine workflow.

## Overview

ByPass Cleaner is built with Tauri 2 + Rust backend + HTML/CSS/JavaScript frontend.

Core goals:
- safe cleanup first (preview and filters before destructive actions)
- observable runtime (live counters, log stream, JSON reports)
- incident-response helpers (process details, SHA256, quarantine, audit trail)

## Key Features

### Cleanup Engine
- Preview-only mode (`dry_run`) and real delete mode
- Filters by file age, minimum size, and extension allowlist
- Optional recursive scan of subfolders
- Optional deletion of empty directories
- Optional hidden-file skip on Windows
- Stop signal during active cleanup run

### Live Dashboard
- Real-time counters: scanned, matched, deleted, freed bytes, errors
- Progress/log streaming to UI
- Report snapshot preview directly in app

### Reports And Settings
- JSON cleanup reports in configurable output folder (`logs` by default)
- Saved settings (`qt_settings.json`) with normalized defaults
- Built-in localization (EN/RU in current UI pack)
- Theme mode (`AUTO` / `DARK` / `LIGHT`) and accent presets

### Process Safety Toolkit
- Process inventory (`list_processes`)
- Process details with hash metadata (`get_process_info`)
- Quarantine/restore flow with manifest files
- Windows reboot-delete scheduling (`schedule_delete_on_reboot`)
- Append-only audit journal (`audit-log.jsonl`)

## Tech Stack

- Rust 1.77.2+
- Tauri 2.10.x
- Frontend: vanilla HTML/CSS/JS (`webui`)
- Windows packaging: Tauri bundle + Inno Setup

## Requirements

- Windows 10/11 x64
- Rust toolchain (via rustup)
- Cargo + Tauri CLI
- WebView2 Runtime (usually preinstalled on modern Windows)
- Optional: Inno Setup 6 (`ISCC.exe`) for custom installer build

## Run In Development

From project root:

```powershell
cargo tauri dev
```

This starts the Tauri app with frontend from `webui` (`frontendDist` is set in config).

## Build Release

From project root:

```powershell
cargo tauri build
```

Typical artifacts:
- app executable: `src-tauri/target/release/bypass-cleaner.exe`
- bundled installers/packages (generated by Tauri) under `src-tauri/target/release/bundle/`

## Build Inno Setup Installer

After release EXE is built:

```powershell
powershell -ExecutionPolicy Bypass -File .\Installer\build_setup.ps1 -AppVersion 1.0.0
```

What script does:
- validates release EXE exists
- generates wizard branding bitmaps in `Installer/Assets/` if needed
- locates `ISCC.exe`
- compiles `Installer/ByPass Cleaner.iss`

Installer output directory is configured in `.iss` as `Installer/Output/`.

## Runtime Data

By default, app writes/uses:
- `qt_settings.json` (settings)
- `logs/cleanup_report_*.json` (cleanup reports)
- `.quarantine/files` and `.quarantine/manifests` (quarantine storage)
- `audit-log.jsonl` (append-only audit log)

Exact location depends on current app root / working directory in runtime.

## Security Notes

- Primary workflow is safety-oriented: inspect -> preview -> action
- Quarantine moves files with metadata manifest and restore support
- Reboot-delete uses native Windows scheduling API
- Audit entries are appended as JSON Lines for traceability
- Force actions are intentionally gated and not default behavior

## Troubleshooting

- `ISCC.exe was not found`:
  install Inno Setup 6 or ensure `ISCC.exe` is in `PATH`
- Missing release EXE for installer build:
  run `cargo tauri build` first
- Build identifier conflicts in Tauri:
  keep unique `identifier` in `src-tauri/tauri.conf.json`
